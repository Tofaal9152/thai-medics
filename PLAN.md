## Protected routes (3 roles)

Guards run in `beforeLoad`, so a blocked user never sees the page or fires its
loaders. Nesting composes them — `_authed` checks login, `admin`/`student` check role.

| Situation | Goes to |
|---|---|
| Guest opens a protected page | `/auth/login?redirect=<page>` |
| Logged in, wrong role | their own role home (never login — that would loop) |
| Logged in, opens `/auth/*` | `?redirect=` if same-site, else role home |
| Logs in / logs out | guards re-run immediately (router.tsx subscription) |

Role homes live in `roles.ts`: ADMIN → `/admin`, STUDENT → `/student`, TEACHER and
UNKNOWN → `/`. Adding a role = one line there + a `_authed/<role>/` folder.

The backend has no `/me` endpoint and its JWTs carry only `user_id`, so `user` and
`role` are saved at login (`profile-storage.ts`) to survive reloads. It is not a
credential — tampering only changes which screens render; the backend still
authorizes every request. A profile that fails validation logs the user out.

Guards are UX, not security: every backend endpoint must check the role itself.

## Ported from the tanstack-start template

Hooks, `lib/http`, `lib/env.ts`, `utils/form-errors.ts`, every route and all of
`features/auth` came over from `../tanstack-start`. Changes made during the port:

- `lib/axios.ts` was folded into `lib/http/api-client.ts` — one client, not two.
- `env.ts` reads `import.meta.env` instead of `process.env`. The `SESSION_*` vars
  were server-only and are gone; a `VITE_`-prefixed secret would ship in the bundle.
- `"use client"` directives and BOMs stripped (no RSC in a Vite SPA).
- `use-mobile` rewritten on `useSyncExternalStore`; `any` generics in
  `use-debounced-callback` and `use-zod-tanstack-form` replaced with typed ones.
- Page chrome moved out of `__root.tsx` into layout routes; `_marketting` was
  renamed `_public`. Auth pages render full-screen.
- The home page's own `ModeToggle` was dropped; the layout header already has one.

### Auth: server functions → client module

`features/auth/server/` could not come over — `createServerFn` and the httpOnly
session cookie both need a server a SPA does not have. `features/auth/api.ts`
replaces it: same function names, same `{ data }` call shape, same return types, so
the route components were ported unchanged. Zod validation moved from
`.validator(schema)` into an explicit `schema.parse()` at the top of each function.

**The refresh token lives in a browser-written cookie** (`auth_refresh_token`,
`features/auth/token-storage.ts`): `SameSite=Strict`, `Secure` on https, `Max-Age`
30 days to match the old session. The access token stays in memory only.

Only a server's `Set-Cookie` can make a cookie httpOnly, so this one is readable by
any script on this origin — against XSS it is no stronger than localStorage.
Encrypting it client-side (e.g. with `jose`) would not change that: the key would
ship in the bundle. To get real httpOnly protection, have the backend set the cookie
on login and accept it on refresh (CORS with credentials); then `token-storage.ts`
becomes no-ops and `api.ts` switches to `withCredentials: true`.

## Notes for later

- `src/routeTree.gen.ts` is generated on dev/build and is committed; it is excluded from ESLint.
- Adding a route = adding a file under `src/routes/`; `Link` types update automatically.
- Tailwind v4 has no config file — theme edits go in the `@theme` block in `src/index.css`.
- The `menu` component does not exist in the base-nova registry; use `dropdown-menu`.
- The main JS chunk is ~540 kB (mostly devtools, which are dev-only in practice).
- `bun run typecheck` is `tsc -b`, not `tsc --noEmit` — the root tsconfig is a
  project-references stub, so `--noEmit` checks nothing.
- `VITE_BACKEND_URL` points at the real backend (`https://dpa-api.2devs.net`).
- Unverified (`NOT_VERIFIED`) logins now store nothing, so a reload can't
  restore them as logged in (the Start template did).
