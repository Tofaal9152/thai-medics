# Project Patterns & Conventions

Vite + React SPA template. There is **no server** — no SSR, no Server Actions, no
server functions. Anything that needs a secret belongs in the backend, not here.

## Stack

- **Build**: Vite 8 + React 19 — client-only SPA, deployed as static files
- **Language**: TypeScript (strict) — path alias `@/` → `src/`
- **Package manager**: bun (`bun.lock`; there is no `package-lock.json`)
- **Routing**: TanStack Router, file-based (`src/routes/`), code-split per route
- **Data fetching**: TanStack Query v5
- **Forms**: TanStack Form v1 + Zod v4
- **HTTP**: Axios via the `request` wrapper (`lib/http/request.ts`)
- **UI**: Tailwind CSS v4 + shadcn/ui, style `base-nova` on **Base UI** (not Radix)
- **Toasts**: Base UI toast manager (`components/ui/toast.tsx`) — not Sonner
- **Backend**: Django (dj-rest-auth + simplejwt), URL from `VITE_BACKEND_URL`

```bash
bun run dev         # http://localhost:5173
bun run build       # tsc -b && vite build -> dist/

bun run lint        # eslint .
```

  and passes silently.
- Before calling work done: `typecheck`, `lint` and `build` must all pass.

## File Structure Pattern

```
src/
├── routes/                     # Thin wrappers only — import pages from features/
│   ├── _public/                # Public route group
│   ├── auth/                   # Guest-only route group (login, signup, ...)
│   └── _authed/                # Authenticated route group
│       ├── admin/              #   ADMIN pages
│       └── student/            #   STUDENT pages
│
├── features/                   # All business logic
│   └── [feature]/
│       ├── pages/
│       │   └── [page]/
│       │       ├── components/ # Page-specific UI
│       │       ├── queries/    # useFetchData + useMutationHandler hooks
│       │       ├── schemas/    # Zod schemas
│       │       └── index.tsx   # Page entry point (default export)
│       ├── types/
│       └── utils/
│
├── components/
│   ├── layout/                 # navbar/, sidebar/                        (create when needed)
│   ├── shared/                 # DataTable, Pagination, form-related/     (create when needed)
│   ├── ui/                     # shadcn/ui (CLI-managed)
│   ├── theme-provider.tsx
│   └── mode-toggle.tsx
│
├── hooks/                      # use-fetch-data, use-mutation-handler, use-zod-tanstack-form,
│                               # use-search, use-debounced-callback, use-mobile
├── lib/
│   ├── env.ts                  # the only place import.meta.env is read
│   ├── http/                   # api-client, request, make-endpoint
│   ├── query-client.ts
│   └── utils.ts                # re-exports `cn`
├── types/                      # shared types — crud, query, route params     (create when needed)
├── utils/                      # form-errors, ...
├── services/                   # e.g. upload-file.service                      (create when needed)
├── main.tsx                    # starts session restore, mounts providers + router
├── router.tsx                  # createRouter; context { queryClient, auth }
└── routeTree.gen.ts            # GENERATED by the router plugin — never edit
```

- Route files are thin wrappers — the page itself lives in `features/`:

  ```tsx
  // routes/_authed/admin/blogs/index.tsx  ->  /admin/blogs
  import { createFileRoute } from "@tanstack/react-router"
  import BlogListIndex from "@/features/blog/pages/blog-list"

  export const Route = createFileRoute("/_authed/admin/blogs/")({ component: BlogListIndex })
  ```
- Access control comes from the folder the route sits in (see Protected routes) — never
  check auth inside a page.
- `features/auth/` is the exception: it is app infrastructure (api, session, guards,
  token/profile storage), not a page feature. The auth pages themselves currently live
  in full inside `routes/auth/**` — they predate this pattern; new pages must not copy that.

## Routing

File-based. A folder's `route.tsx` is its layout (renders `<Outlet />`); `index.tsx`
is the folder's own page. `_name` folders are pathless — they group routes without
adding a URL segment.

```
routes/
├── __root.tsx          # bare: Outlet + Toaster + devtools. No page chrome here.
├── _public/            # public — route.tsx holds the nav chrome
├── auth/               # guest-only — logged-in users are redirected out
└── _authed/            # login required — route.tsx holds the app shell
    ├── admin/          # ADMIN only    -> /admin/...
    └── student/        # STUDENT only  -> /student/...
```

- The plugin regenerates `routeTree.gen.ts` on `dev`/`build` and rewrites the path
  string in `createFileRoute("...")` to match the file's location.
- Links are type-checked: `<Link to="/admin">`. Pass dynamic strings through
  `redirect({ href })`, not `to`.
- Put `beforeLoad`/`loader` on routes, not effects in components.

### Protected routes

Guards live in `features/auth/guards.ts` and run in `beforeLoad` — before render and
before loaders, so blocked users never see a flash of the page or fire its requests.
Nested layouts compose them.

| Guard | Used in | Behaviour |
|---|---|---|
| `requireAuth(context.auth, location.href)` | `_authed/route.tsx` | guest -> `/auth/login?redirect=<page>` |
| `requireRole(context.auth, "ADMIN")` | `_authed/<role>/route.tsx` | wrong role -> that user's role home (never login — it would loop) |
| `requireGuest(context.auth, location.search)` | `auth/route.tsx` | logged in -> same-site `?redirect=` or role home |

- Role -> home mapping is in `features/auth/roles.ts` (ADMIN `/admin`, STUDENT
  `/student`, TEACHER/UNKNOWN `/`). Change it there; never compare roles inline.
- `router.tsx` re-runs guards (`router.invalidate()`) whenever auth status or role
  changes. So after login, **don't `navigate()`** — `setAuthenticated` makes the
  `/auth` guard send the user on. One place decides where users land.
- **Guards are UX, not security.** Every backend endpoint must authorize by role.

## Auth

- **Access token**: memory only (`features/auth/store/auth-store.ts`), read by the
  axios interceptor via `authStore.getState()`. Never persist it.
- **Refresh token**: first-party cookie `auth_refresh_token`
  (`features/auth/token-storage.ts`) — SameSite=Strict, Secure on https, 30 days. It
  is JS-readable (only a server `Set-Cookie` can make it httpOnly), so XSS can steal
  it. Client-side encryption (e.g. `jose`) does not help — the key would ship in the
  bundle.
- **Profile** (`user` + `role`): localStorage `auth-profile`, zod-validated on read.
  Needed because the backend has no `/me` endpoint and JWTs carry only `user_id`.
  Not a credential; an invalid profile logs the user out.
- **Boot**: `ensureAuthReady()` (features/auth/session.ts) starts in `main.tsx`.
  Guards await it; public pages don't. `status` is `"pending"` until it settles —
  render nothing auth-dependent while pending.
- **Login**: only `status === "LOGIN_SUCCESS"` persists anything. `NOT_VERIFIED`
  (student awaiting OTP) stores nothing.
- **Logout**: `logout()` from `features/auth/session.ts` — never call
  `authStore.setUnauthenticated()` + `logoutFn()` by hand.
- `features/auth/api.ts` uses a bare axios instance on purpose: auth calls must not
  pass through `apiClient`'s 401-refresh interceptor, which calls back into it.
- To move to backend-set httpOnly cookies later: only `token-storage.ts` and `api.ts`
  change (`withCredentials: true`). The login API docs say the backend already sets
  `access_token`/`refresh_token` httpOnly cookies — worth checking first.

## API Call Pattern

| Client | File | When to use |
|---|---|---|
| `apiClient` | `lib/http/api-client.ts` | All app API calls — authenticated or not (no token -> no header) |
| bare `authClient` | `features/auth/api.ts` | Auth endpoints only — must bypass the 401 interceptor |

- Never call Axios directly — always use `request.get/post/put/patch/delete/postFormData`
  (`lib/http/request.ts`). It returns `res.data`, typed: `request.get<T>(url)`.
- `apiClient` request interceptor: attaches `Authorization: Bearer <access>` from the
  in-memory auth store.
- `apiClient` response interceptor: on 401 -> refreshes the access token once and
  retries; if the refresh fails, logs the user out (guards then redirect to login).
- Build query strings with `makeEndpoint(baseUrl, paramsObj)` — skips
  null/undefined/`""` values automatically, repeats keys for arrays.

## Data Fetching Pattern

- Always use `useFetchData` — never call `useQuery` directly in feature code.
- Signature: `useFetchData<T>({ url, querykey, options })`
- Query key convention: `[SCREAMING_SNAKE_CASE_CONSTANT, paramsObject]`
- Define the key constant at the top of the query file:
  `export const BLOG_DETAILS_QUERY_KEY = "blog-details"`
- Pass the full params object as the second key element so React Query refetches on change.

**Query defaults** (`lib/query-client.ts`): `staleTime` 60s · `retry` 1 · no refetch on window focus

## Mutation Pattern

- Always use `useMutationHandler` — never call `useMutation` directly in feature code.
- Key options: `mutationFn`, **`debugLabel` (required)**, `invalidateKeys` (array of
  QueryKeys), `successMessage`, `errorMessage`, `showSuccessToast` (default true),
  `showErrorToast` (default true), `onSuccess`, `onError`, `debug` (dev-only logs).
- `invalidateKeys` is busted after every successful mutation. `[[KEY]]` also matches
  every `[KEY, params]` query, so one entry refreshes all pages/filters of a list.
- Error toast text: the API's `message`, else `errorMessage`, else "Something went wrong".

### Example — `features/blog/pages/blog-list/queries/use-blog.ts`

```ts
import { useFetchData } from "@/hooks/use-fetch-data"
import { useMutationHandler } from "@/hooks/use-mutation-handler"
import { makeEndpoint } from "@/lib/http/make-endpoint"
import { request } from "@/lib/http/request"
import type { BlogFormValues } from "../schemas/blog.schema"
import type { BlogListResponse } from "@/features/blog/types/blog.type"

export const BLOG_LIST_QUERY_KEY = "blog-list"

export function useBlogList(params: { page: number; search: string }) {
  return useFetchData<BlogListResponse>({
    url: makeEndpoint("/blogs/", params),
    querykey: [BLOG_LIST_QUERY_KEY, params],
  })
}

export function useCreateBlog() {
  return useMutationHandler({
    debugLabel: "CreateBlog",
    mutationFn: (data: BlogFormValues) => request.post("/blogs/", data),
    invalidateKeys: [[BLOG_LIST_QUERY_KEY]],
    successMessage: "Blog created",
  })
}
```

## Table Pattern

- Library: TanStack React Table v8 via a shared `<DataTable>` component.
  **Not in this template yet** — first time a table is needed: `bun add @tanstack/react-table`
  and create `components/shared/data-table.tsx` + `components/shared/pagination.tsx` with the
  APIs below.
- Columns defined as `ColumnDef<T>[]` in a separate `[name]-column.tsx` file.
- `<DataTable data columns loading error />` — loading shows spinner, error shows message.
- `<Pagination page total onPageChange />` — `total` is item count (divided by 10 internally).
- Search/filter state lives in the table component as `useState` (debounce with
  `useSearch`); passed into the query hook's params object.

## Form Pattern

**TanStack Form + Zod** (all API mutation forms):
- `useZodTanstackForm({ defaultValues, schema, mutation, fieldLabels })` returns
  `{ form, resetAll, submitErrors, errorSummary, ... }`; it resets the form after
  `mutation.mutateAsync` succeeds.
- Fields use `<form.Field name="x">{(field) => <FormFieldWrapper field={field} label="X">{(p) => <Input {...p.inputProps} />}</FormFieldWrapper>}</form.Field>`
- `p.inputProps` spreads id/name/value/onBlur/onChange/aria-invalid onto the input.
- `p.onChangeValue(val)` for non-native inputs (select, checkbox, etc.).
- Show validation errors with `<SubmitErrorSummary errors={submitErrors} />`.
- Submit with `<SubmitButton isLoading={mutation.isPending}>`.
- Zod schema lives in `schemas/[name].schema.ts`; export both schema and
  `type X = z.infer<typeof XSchema>`.
- `FormFieldWrapper`, `SubmitErrorSummary` and `SubmitButton` go in
  `components/shared/form-related/` — **not in this template yet**; create them with the
  API above the first time a form needs them, built on `components/ui/field.tsx`
  (`Field`, `FieldLabel`, `FieldError`).
- The existing auth pages use `useForm` + `Field` directly (no wrapper) and can serve as
  markup reference: `routes/auth/login/index.tsx`.

## UI

- **Base UI, not Radix**: compose with the `render` prop, not `asChild`:
  `<Button render={<Link to="/x">Go</Link>} />`,
  `<DropdownMenuTrigger render={<Button />} />`.
- `cn` comes from the `cn` package (`lib/utils.ts` re-exports it).
- Toasts: `toast.add({ title, type })` from `@/components/ui/toast`, `type` one of
  `success | info | warning | error`. `<Toaster />` is mounted once in `__root.tsx`;
  the manager is a module singleton, so it also works outside React.
- Dark mode: `useTheme()` from `components/theme-provider.tsx`; Tailwind `dark:`
  variants key off the `.dark` class on `<html>`.
- **shadcn CLI gotcha**: `shadcn add` once deleted all of `src/lib/` (including
  non-shadcn files). Commit before running it, then check `git status` after.
- The base-nova registry has `dropdown-menu`, not `menu`.

## Environment

- Only `VITE_*` vars reach the app, and **every one is inlined into the public JS
  bundle**. Never put a secret in `.env` — no session keys, API secrets or tokens.
- Read env only through `lib/env.ts`; type new vars in `src/vite-env.d.ts`.
- `.env` is git-ignored; keep `.env.example` current.

## Coding Conventions

| Thing | Convention | Example |
|---|---|---|
| Files & folders | kebab-case | `use-fetch-data.ts`, `blog-details-table.tsx` |
| Route files | router tokens | `route.tsx`, `index.tsx`, `$id.tsx`, `_authed/` |
| Page entry | `index.tsx`, default export | `export default function BlogListIndex()` |
| Components | PascalCase | `function BlogForm()` |
| Hooks | camelCase, `use` prefix | `useBlogList` |
| Query key constants | SCREAMING_SNAKE_CASE | `BLOG_DETAILS_QUERY_KEY` |
| Types/Interfaces | PascalCase | `type BlogData` |
| Zod schemas | PascalCase + `Schema` suffix | `BlogSchema` |
| Schema / type files | `[name].schema.ts` / `[name].type.ts` | `blog.schema.ts` |
| Table columns / table | `[resource]-column.tsx` / `[resource]-table.tsx` | `blog-column.tsx` |

- **No `"use client"`** — it is a Next.js directive and means nothing here.
- No `any`: ESLint's `no-explicit-any` is an error. If a cast is unavoidable, cast
  through `unknown` to a named type and leave a comment saying why.
- Route files and `components/ui/` are exempt from `react-refresh/only-export-components`
  (see `eslint.config.js`); everything else must export only components.
- `features/auth/schema.ts` uses camelCase schema names (`loginRequestSchema`) — it
  predates this table; don't rename it, don't copy it.

## When Adding a New Page

1. Create `src/features/[domain]/pages/[page]/` with subfolders: `components/`, `queries/`, `schemas/`
2. Create `queries/use-[resource].ts` — export a `QUERY_KEY` constant + `useFetchData` hook
   (and its `useMutationHandler` hooks)
3. Create `components/[resource]-column.tsx` — export `ColumnDef<T>[]` array
4. Create `components/[resource]-table.tsx` — manage `page`/`search` state, call the query
   hook, render `<DataTable>` + `<Pagination>`
5. Create `index.tsx` — page entry point (default export), imports the table component
6. Create the route wrapper under the right group — `routes/_authed/admin/...`,
   `routes/_authed/student/...` or `routes/_public/...` — a single `createFileRoute` that
   renders the page from `features/`. The folder's guard applies automatically.
7. Add the nav item — `[role]-sidebar-nav-items.ts` under `components/layout/sidebar/`
   once the sidebar exists; until then, the `_authed/route.tsx` header.

## When Adding a New Role

1. Add it to `authRoleSchema` (`features/auth/schema.ts`) if the backend added it.
2. Map its home in `ROLE_HOME` (`features/auth/roles.ts`).
3. Create `routes/_authed/<role>/route.tsx` with `requireRole(context.auth, "<ROLE>")`
   and an `index.tsx`.

## When Adding a New API Call

Goes in the page's `queries/use-[resource].ts` (see the Mutation Pattern example).

**GET**: `useFetchData<ResponseType>({ url: makeEndpoint("/path/", params), querykey: [KEY, params] })`

**POST/PUT/PATCH**: `useMutationHandler({ debugLabel: "X", mutationFn: (data) => request.post("/path/", data), invalidateKeys: [[KEY]], successMessage })`

**DELETE**: `useMutationHandler({ debugLabel: "X", mutationFn: () => request.delete("/path/id/"), invalidateKeys: [[KEY]], successMessage })`

**File upload**: use `request.postFormData("/path/", formData)` as the `mutationFn`

**Auth endpoint**: add a function to `features/auth/api.ts` (bare client, not `request`).

New or changed backend endpoints come from the `api-sync` skill's changelog — it only
reports; integrate on explicit ask, following the steps above.

## Git & Deploy

- Branch `main`. Use the `git-flow` skill: `claude:commit`, `claude:push`,
  `claude:deploy`.
- `.github/workflows/deploy.yaml` deploys only when a push to `main` has
  `nightfury:deploy` in the commit message (or on a manual run). It builds with bun
  and copies `dist/` to the VPS; nginx serves it statically and must fall back to
  `index.html` (`try_files $uri $uri/ /index.html;`).
- `ENV_FILE` secret = the build-time `.env` — public config only (`VITE_BACKEND_URL`).
- Never commit `api-doc/` (git-ignored) — its Bruno files contain real credentials.
